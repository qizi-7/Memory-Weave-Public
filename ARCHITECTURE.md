# Architecture

This source tree implements Memory Weave Next, a local macOS ARM64 archive application. It has three execution boundaries: a React renderer, the Electron main process, and Node workers. The native SQLCipher helper reads WeChat snapshots; the application workspace uses Node SQLite. The repository contains source, not an Alpha installation or a user archive.

| Flow | Follow the source |
| --- | --- |
| Startup and isolation | [package.json](app/package.json) starts [electron/main.cjs](app/electron/main.cjs). It calls `initializeProfile` in [profile-isolation.cjs](app/electron/profile-isolation.cjs) before starting workers. The profile owns the workspace and Chromium session; validation requires a separate temporary profile. |
| UI and IPC | [index.html](app/index.html) loads [src/main.tsx](app/src/main.tsx). [preload.cjs](app/electron/preload.cjs) exposes `window.archive`; main registers the routes and validates source access before dispatching. The writer in [worker.cjs](app/electron/worker.cjs) owns mutations. Directory, favorites lists, media index and diagnostic reads are routed through [archive-view-worker.cjs](app/electron/archive-view-worker.cjs); [latest-stats.cjs](app/electron/latest-stats.cjs) manages cancellable statistics work. |
| JSON archive and views | `Store.importFile` / `importData` in [store.cjs](app/electron/store.cjs) write the local workspace. The `effective` view combines original messages with local edits. [archive-views.cjs](app/electron/archive-views.cjs) handles archive queries and favorites; [archive-projection.cjs](app/electron/archive-projection.cjs) manages derived facts. Writes notify the renderer through `archive:messages-committed`. |
| WeChat history and incremental sync | [account-settings.tsx](app/src/account-settings.tsx) calls the connection routes. Main's `startSync` sends `connectWeChat` to the writer, which calls `importWeChat` in [wechat-adapter.cjs](app/electron/wechat-adapter.cjs). [wechat-snapshot.cjs](app/electron/wechat-snapshot.cjs) prepares a temporary copy with WAL checks; [wechat-batch-reader.cjs](app/electron/wechat-batch-reader.cjs) talks to [native/reader.c](app/native/reader.c). The adapter normalizes rows and saves checkpoints, gaps and retry state. [auto-sync.cjs](app/electron/auto-sync.cjs) schedules authorized incremental runs; [wechat-incremental.cjs](app/electron/wechat-incremental.cjs) and [wechat-integrity.cjs](app/electron/wechat-integrity.cjs) verify source identity and prior data boundaries. |
| Message and media display | [message-content.cjs](app/electron/message-content.cjs) converts raw payloads to display structures. [message-body.tsx](app/src/message-body.tsx) uses local media URLs; the protocol handler in main calls `mediaResponse` in [message-media.cjs](app/electron/message-media.cjs). [wechat-media-db.cjs](app/electron/wechat-media-db.cjs) resolves local database references, and [wechat-image.cjs](app/electron/wechat-image.cjs) handles local image and sticker formats. Preview failures are represented explicitly; there is no CDN download in this flow. |
| AI retrieval | [integrations.tsx](app/src/integrations.tsx) calls the AI IPC routes. [ai.cjs](app/electron/ai.cjs) reads visible messages from `effective`, uses [knowledge-text.cjs](app/electron/knowledge-text.cjs) to build chunks, and requests embeddings and answers from a loopback Ollama endpoint. Manifests track model and source revision; results retain original message references. [local-runtime.cjs](app/electron/local-runtime.cjs) handles local runtime readiness. |

Source archive, temporary source snapshots, the app's workspace and derived indexes are distinct. Trace writes and credentials by following their actual routes: [wechat-vault.cjs](app/electron/wechat-vault.cjs) is separate from message rendering, and temporary source data is not an input to the release workflow. For file-level navigation use [CODE_MAP.md](CODE_MAP.md).
